# 异常检测、归因与预测规则（analyze 阶段）

本文件是「业务指标异常检测与归因分析、辅助决策与预测建议」的唯一方法来源。所有数值由 `scripts/analyze_metrics.py` 产出；模型负责业务解读与建议撰写，**禁止自行计算或改写任何统计量**。

## 1. 指标聚合与同环比口径

- 聚合方式：sum / mean / count / count_distinct；分桶粒度 day（YYYY-MM-DD）/ week（YYYY-Www，ISO 周）/ month（YYYY-MM）。
- 时间序列按全范围分桶，无数据周期 value=null 并在 warnings 声明缺口；图中断开不连线。
- 环比 previous_period = 上一周期；同比 same_period_last_year = 去年同期周期；fixed = 固定基线 constant。
- **除零规则**：基线为 0 时 pct=null + note「基线为 0, 百分比不可计算」，绝不输出 inf 或臆造百分比。
- 聚合无数据（分桶内无可解析值）：sum/mean 为 null；count 为 0。

## 2. 异常检测三法（可组合）

| 方法 | 参数 | 适用场景 | 不报警条件 |
|---|---|---|---|
| iqr 围栏 | iqr_k（默认 1.5），[q1-k·IQR, q3+k·IQR] | 通用首选，对偏态稳健 | IQR=0（近常量序列） |
| mad_z 稳健 z 分数 | mad_z（默认 3.5），z=0.6745·(x-中位数)/MAD | 含极端值的长尾序列 | MAD=0 |
| threshold 固定阈值 | thresholds{别名: [下限, 上限]} | 业务红线（如库存下限、预算上限） | — |

- 有效数据点 < 4 时整体跳过并 warnings 说明（降级，不崩溃）。
- severity 分级：iqr 按超出幅度占 IQR 比例（≥1 high / ≥0.5 medium / 否则 low）；mad_z 按 |z|（≥2×阈值 high / ≥1.5× medium）；threshold 一律 medium（业务红线由用户定性）。
- 同一周期多方法命中会分别列出，模型解读时应合并叙述并注明各方法一致性。

## 3. 归因分析（差额分解法）

- 对比期：目标指标最后一个有效周期 vs 前一个有效周期；有效周期 < 2 时跳过。
- 公式：贡献_d = 当期_d − 基期_d（按求和口径）；**Σ 各维度贡献 = 总差额**（恒等，可校验）。
- top_n（默认 5，≤20）按 |贡献| 降序，其余归并「其他」；share = 贡献/总差额，**总差额为 0 时 share=null + note**。
- 维度取值空缺归入「(空)」；高基数维度（>50）合并为 top-49 + 其他。

### 归因假设标注规范（模型纪律）

- 脚本输出的是**数量贡献**，不是业务因果。模型撰写归因时每条必须标注「假设」，并给证据强度：强（数据内直接可见，如某维度贡献占比突出）/ 中（需业务背景佐证）/ 弱（推测）。
- 禁止写成因果定论（「因为直播渠道下滑所以总销售额下降」×；「直播渠道贡献 −69,375，占总差额的 −16.7%，是主要拖累项（假设，证据强度：强）」√）。
- 进一步下钻建议（如需要按 region 二次归因）以「建议下一步」形式提出，不擅自执行。

## 4. 轻量预测三法

| 方法 | 参数 | 最少数据点 | 外推形式 |
|---|---|---|---|
| moving_average | window（默认 3，2..24） | ≥ window | 最近 window 期均值，预测值回代逐期滑动 |
| linear | 无 | ≥ 3 | 最小二乘直线外推 |
| exp_smoothing | alpha（默认 0.5，(0,1)） | ≥ 2 | 简单指数平滑水平外推 |

- 预测区间：历史残差样本标准差 × 1.28（约 80% 朴素区间）；残差 < 2 个时区间宽度为 0（仅点预测）。
- horizon 1..24；数据不足时 forecast.points=[] + note（降级不崩溃）。
- **limitations 文案由脚本内置输出**（方法局限 + 通用免责），模型在报告与叙述中必须原样引用，不得删改。

## 5. 结论与行动建议纪律

- 每条结论必须可回溯到脚本输出字段（哪个指标、哪个周期、哪个数值），禁止凭印象给数字。
- 行动建议围绕：异常点核查建议（指向具体周期与维度）、归因假设验证建议（需补充什么数据/业务信息）、预测参考下的备货/预算类提示；建议措辞由模型负责，数值引用由脚本负责。
