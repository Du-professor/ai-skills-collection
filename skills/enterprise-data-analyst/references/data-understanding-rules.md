# 数据理解规则（profile 阶段）

本文件是「数据获取与理解」阶段的唯一规则来源。画像数值一律由 `scripts/profile_dataset.py` 产出，模型只负责复述、解释与确认，不得自行估算任何统计量。

## 1. 列类型推断阈值表

| 类型 | 判定条件（对非空值抽样，取前 2000 个） | confidence |
|---|---|---|
| integer | 整型正则命中率 ≥ 0.9 | 命中率 |
| float | 宽松数值解析（千分位/货币/百分号/括号负数/全半角）成功率 ≥ 0.9 | 成功率 |
| date | 多格式日期解析成功率 ≥ 0.9 | 成功率 |
| boolean | 全部取值 ∈ {true,false,yes,no,y,n,是,否,对,错}（大小写不敏感） | 1.0 |
| enum | 唯一值个数 ≤ min(20, max(3, n×5%)) | 0.8 |
| text | 以上均不满足 | 1.0 |

- 判定顺序固定：integer → float → date → boolean → enum → text，前者命中即停。
- 空值（None 或纯空白）不参与判定；`missing_rate` 单独报告。
- 百分号解析口径：`50%` → `0.5`；货币符号 `¥￥$€£` 与千分位逗号剔除；`(2,500)` → `-2500`。
- 日期歧义格式（如 `01/02/2026`）按列级多数决：单边 >12 的值提供证据，MDY/DMY 证据多者胜出；无证据时默认 MDY 并在 warnings 中声明。口径假设必须向用户复述。

## 2. 业务问题确认四问（一次性合并提问）

进入分析前必须与用户对齐四件事，缺什么问什么，只问一次：

1. **指标**：关心哪些数值列？业务名称与口径（如「销售额=amount 求和」）。
2. **维度**：按什么切片？（渠道/地区/门店……）
3. **时间**：时间列是哪一列？分析粒度（日/周/月）？对比基线（环比/同比/固定基线/无）？
4. **产出**：默认产出单文件 HTML 分析报告；如只要清洗后数据或只要结论文字，在此声明。

用户说「你看着办」时采用默认口径：数值列 sum 聚合、全部 enum/text 低基数列为维度、时间列取 suspected_time_columns[0]、粒度月、基线环比、产出 HTML 报告。默认口径必须在报告中声明。

## 3. 画像警告严重度分级

| 级别 | 含义 | 处置 |
|---|---|---|
| 阻断 | 无法继续：0 数据行、无表头、格式不支持 | 脚本 exit 2/1，向用户说明并请求修复输入 |
| 降级 | 可继续但结论受限：行数截断、公式无缓存值、JSONL 坏行、日期歧义默认口径、编码容错 | 继续执行，warnings 落盘，报告「降级点」节逐条说明 |
| 提示 | 不影响计算：敏感列检出、常量列、全空列、重复表头重命名 | 继续执行，画像/报告中单句说明 |

## 4. 数据理解复述规范

画像完成后，模型用一段话向用户复述：行列规模与时间范围、每个列的类型与置信度、缺失与异常初步印象、敏感列与警告。复述中的数字必须逐字来自画像 JSON，不得四舍五入改写；随后给出清洗策略建议（规则见 [清洗策略](cleaning-policy.md)）并展示影响面，经用户确认后执行。
