# 交互协议（Interaction Protocol）

> 本文件规范**输入收集顺序、模糊澄清话术、以及高德地图 MCP 的条件调用与降级提醒话术**。

---

## §1 输入收集顺序（一次性）

缺失项只允许提**一个合并问题**收集，不逐项追问。默认值优先取自偏好档案（见 `preference-schema.md`）。

1. **出发地**（国内城市）
2. **国内目的地**（城市/地区）
3. **出行日期 + 天数**
4. **预算档位 + 上限**（economy/comfort/luxury + 金额）
5. **同行人类型**（单人/情侣/家庭/朋友/商务）
6. **兴趣标签**（可多选）
7. **饮食禁忌**（可空）

示例合并问句：
> 为了给您定制行程，还差几点信息：出发城市、大概出行日期和天数、总预算上限、以及同行的有谁？其余（兴趣、忌口）有默认就按您以往偏好来。

## §2 模糊输入澄清

- “想放松” → 映射 `休闲` + `自然`，并一句澄清：“是想近郊自然风光，还是城市休闲观光？”
- 兴趣为空 → 用偏好标签，无则默认 `城市观光 + 美食`。
- 日期格式多样（`8月1日`/`08/01`）→ 归一化为 ISO `YYYY-MM-DD`；无法解析则澄清，不猜测。
- 预算只说“不多” → 按同行人/目的地给一档默认并明示假设。

## §3 高德地图 MCP 条件调用与降级提醒

### 检测可用性
运行时检查当前可用工具集中是否存在**高德地图 MCP 连接器**暴露的工具（如路线规划 / 天气 / 实时路况 / 周边搜索；具体工具名以连接器实际暴露为准，不硬编码）。

### 可用时（realtime）
- 调用高德工具获取：关键路段实时路况、目的地实时/预报天气、城间/市内路线耗时。
- 结果填入对应 segment / `weather_traffic_notes`，每条标 `source="realtime"`。
- 行程单顶部写：`✅ 已接入高德地图实时数据（天气/路况）`。
- 写 `meta.data_source_note = "realtime"`。

### 不可用时（estimate）— 固定提醒文案
行程单顶部及每个 estimate 提醒区块，统一附：

> ⚠️ 数据基于知识库估算，非实时，请以高德地图为准。建议在高德地图查看：<操作提示或 https://www.amap.com/... 链接>。

- `weather_traffic_notes` 每条标 `source="estimate"`，`text` 为按季节/城市经验值估算。
- 写 `meta.data_source_note = "estimate"`。

### 部分可用
如天气可用、路况不可用：能取到的标 `realtime`，取不到的标 `estimate` 并附提醒，**绝不因单点失败整体中断**。

### 联网纪律
除高德地图（经 MCP 连接器）外，不发起任何其它网络请求；脚本内禁止任何网络调用。渲染中的 amap 链接仅为 `<a>` 锚点，点击才联网，不算 Skill 主动请求。
