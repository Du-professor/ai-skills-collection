# 通用对比维度清单

本清单是技术选型利弊分析的**检查清单**，不是必答清单。使用时根据需求锚定阶段确认的约束裁剪维度，并为具体决策补充特有维度。

使用规则：
- 每个被选中的维度下，对每个候选方案同时写**优势、劣势、风险**三栏
- 结论一律条件化："在 X 条件下 A 占优"，禁止无条件断言
- 不评分、不排名、不设权重

---

## 1. 功能性（Functionality）

候选方案"能做什么"。检查项：

- 核心能力覆盖：对需求清单中的必备功能，各方案是原生支持、插件支持、还是需要自行开发？
- 高级特性：超出必备项的差异化能力（如数据库的 JSONB/全文检索/GIS，缓存的持久化/发布订阅/脚本）
- 功能实现质量：同名功能的实现深度差异（例如都"支持 JSON"，索引机制可能完全不同——标注版本号验证）
- 功能冗余度：为用不到的能力付出的复杂度代价是否可接受

常见陷阱：官方功能列表只说明"有"，不说明"好用"。功能实现质量需要第三方实测佐证。

## 2. 性能（Performance）

- 负载匹配度：性能结论必须绑定负载类型（读写比、数据规模、并发量、热点分布）。脱离负载类型的"谁更快"没有决策价值
- 基准测试口径：数据来源的测试条件（硬件、版本、数据集规模、客户端数）是否可比；官方基准通常对自家有利，降档处理
- 尾部延迟：p99/p999 与平均值的差异，JIT 预热、GC 暂停、持久化刷盘等尖刺来源
- 扩展曲线：垂直扩展上限、水平扩展方式（原生集群 / 客户端分片 / 中间件）及扩容时的性能拐点
- 资源效率：达到同等吞吐所需的 CPU/内存/存储成本

## 3. 稳定性（Stability）

- 成熟度与生产验证：主版本年龄、大规模生产案例（可考证的）、LTS 政策
- 故障模式：典型故障场景及表现（如缓存雪崩、复制延迟、脑裂），社区是否有公认的缓解方案
- 数据安全：一致性模型、崩溃恢复机制、持久化保证（区分"写前日志"与"写后日志"类保证）
- 版本节奏：发版频率与破坏性变更历史；升级路径是否平滑
- 已知缺陷：issue tracker 中长期未修的硬伤、官方承认的限制

## 4. 运维成本（Operational Cost）

- 部署与配置：默认配置的可用程度、生产化所需的调参工作量
- 监控与排障：官方/第三方监控工具、可观测性成熟度、故障排查资料的丰富度
- 高可用方案：原生 HA 方案成熟度 vs 需要外置组件（如 etcd、ProxySQL）
- 备份与恢复：工具链、恢复时间目标（RTO）可达性
- 托管服务：云厂商托管选项的丰富度与价格（多一个托管选项 = 少一份运维负担）
- 人力匹配：团队现有技能与方案运维要求的差距，招人补位的难度

## 5. 生态成熟度（Ecosystem Maturity）

- 社区活性：贡献者数量与多样性（警惕单一公司主导）、issue/PR 响应速度
- 文档质量：官方文档完整度、中文资料可得性（对中文团队是实际影响因素）
- 周边工具：客户端库、ORM 支持、框架集成、IDE/调试工具
- 招聘市场：掌握该技术的人才供给（可参考招聘网站职位量、开发者调查）
- 商业支持：背后组织、商业公司存续状况、企业版/云版的可持续性
- 生态位趋势：采用度在上升还是下降（如近年的新项目默认选择），但注意区分"声量"与"实际采用"

## 6. 技术风险（Technical Risk）

尚未发生但可能引爆的问题：

- 许可证风险：许可证变更历史（如近年多个基础设施软件的许可证收紧事件）、对商业使用的限制
- 治理风险：单一公司/个人控制程度、分叉的可能性与已有先例
- 锁定风险：数据格式、协议、API 的专有程度；与特定云厂商的绑定深度
- 路线风险： roadmap 与自身需求的错位、核心维护者流失迹象
- 安全态势：CVE 历史频率与严重程度、修复响应速度、安全公告机制

## 退出成本（Exit Cost）——每个选型都必须单独评估

替换该方案的代价：

- 数据迁移：数据导出格式是否开放、迁移工具成熟度、迁移窗口期的一致性保障难度
- 代码耦合：业务代码对专有 API/语法/扩展的依赖面
- 技能沉没：团队在该方案上积累的运维经验、调优知识的可迁移性
- 切换策略：是否支持渐进式迁移（双写、影子流量）还是只能硬切

## 常见决策类型的补充维度

| 决策类型 | 建议补充维度 |
|---|---|
| 数据库 | 事务模型与隔离级别、JSON/半结构化支持、复制机制（物理/逻辑）、分区能力、GIS/时序等专用扩展 |
| 缓存/中间件 | 数据结构丰富度、持久化与恢复、线程/并发模型、内存效率、集群拓扑与扩容方式 |
| 前端框架 | 招聘市场与团队学习曲线、框架完整度（全家桶 vs 拼装）、SSR/SSG 方案、构建工具链、移动端延伸能力 |
| 编程语言 | 运行时性能特征、包管理与生态库覆盖、类型系统、构建/部署复杂度、团队招聘难度 |
| 云服务 | 计费模型与成本可预测性、SLA、区域覆盖、迁移出该云的成本 |
