# 交互协议（Interaction Protocol）

本文件规定 Skill 与用户交互时如何**一次性收集必要输入**、如何**分发到四类模式**、以及如何处理**原文来源**。遵循"Skill 自己编排流程，不询问用户用什么方法/格式"的原则。

---

## 一、一次性收集必要输入

开始任何解读前，需确定以下信息；若用户未一次性提供完整，只提出**一个合并问题**补齐缺失项，不要逐项追问。

| 字段 | 取值 | 说明 |
|---|---|---|
| `mode` | `summary`/`extract`/`compare`/`qa` | 用户意图不明时，按"既能摘要也能提取"默认进入 `summary`+`extract` 组合，或询问"您想摘要、提取要点、对比还是问答？" |
| 原文来源 | 粘贴文本 / 本地文件 / 待提供 | 见第三节 |
| 对比份数 | ≥2（仅 compare） | compare 模式必须收到 ≥2 份政策，否则提示补充 |

不要询问：希望用什么解析方法、什么报告格式、什么模型——这些由 Skill 内部决定。

---

## 二、模式分发逻辑

- **摘要/要点**：单份政策即可，二者常组合输出。
- **对比**：必须已收集 ≥2 份政策原文，分别解析后调用 compare 模式。
- **问答**：需先有已解析的原文（可来自本次粘贴/文件，或跨会话记忆中已记录的政策——经 `policy_store.py` 调取元信息后请用户确认是否基于该政策作答）。

---

## 三、原文来源处理

| 来源 | 处理方式 |
|---|---|
| 用户直接粘贴的文本/Markdown | 直接使用，作为唯一事实源 |
| 本地 `.txt` / `.md` | 用内置读取（文本模式）直接读入 |
| 本地 `.docx` | 调用 stdlib 解析（zipfile + ElementTree 提取正文）；损坏/加密则提示用户粘贴 |
| 本地 `.pdf` | **不支持自动解析**——提示用户复制正文粘贴 |
| 其他格式 / 不存在 / 无权限 | 明确告知用户，请改用粘贴或受支持格式 |
| 远程链接 / URL | 不主动下载；请用户粘贴内容（避免联网与注入风险） |

无论来源，原文一旦读入即视为**唯一事实源**；模型输出的一切结论必须锚定原文。

---

## 四、确认与交付

- 生成报告前调用 `validate_policy.py` 校验；失败按字段级错误重试 ≤2 次。
- 调用 `policy_store.py --action record` 记录本次解读（不可写则静默降级）。
- 调用 `render_report.py` 生成自包含 HTML 报告（默认）与 Markdown 回退，并展示给用户。
- 报告内已强制注入免责声明与数据隐私说明。
